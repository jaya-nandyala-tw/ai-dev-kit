# memories/

This directory is the harness's durable, file-based memory — read and written by the agents in
`.github/agents/` and skills in `.github/skills/`. It ships empty (just `.gitkeep` placeholders);
the content is generated by using the harness on your own repo.

## `memories/repo/`

Durable, per-repo index files that agents check **before** loading a full spec file — cheap lookups
instead of expensive reads. Referenced throughout `.github/agents/` and `.github/instructions/` as
"the memory index." Populate these yourself, or have `@doc-garden` help keep them current:

- `routes.md` — UI routes / screen map
- `api-index.md` — all API endpoints
- `data-models.md` — DB tables and shapes
- `toggles.md` — feature toggle registry (if your project uses feature flags)

Add your own index files here as patterns emerge — the convention is "one file per thing an agent
would otherwise have to grep the whole codebase to find."

## `memories/session/`

Ephemeral per-story checkpoint files, one per active ticket: `story-{TICKET-XXXX}.md`. Written by
`@groom` at intake, updated by `@story` as a story moves through phases, and collapsed to a two-line
closed marker by `@story`'s Close phase. These are a *resume pointer*, not the source of truth — the
plan file in `plans/active/` (or `plans/completed/`) always is. See `global.instructions.md` §
Checkpoint / Plan Self-Consistency for the invariant these files must maintain.

Session files are working state, not permanent history — safe to delete once a story is fully closed
and archived, though leaving the two-line closed marker behind is harmless and helps `@groom`'s Resume
Check short-circuit correctly if the ticket ID ever comes up again.
